# 自由弹珠录音保存与恢复实测

本次接续 `fix/v21-reliability-redesign` 的 `504aed02293548c97316685f4960cfcfc08edfad`。修改限于录音数据通路与后续新增的本地启动入口。弹珠页面的 JSX 与原提交逐字符一致，其他页面、组件、CSS 和图片素材的 Git 差异为空。

最近八秒的有效碰撞现在以物理碰撞批次同步更新 Zustand，沿用现有 localStorage 保存，并立即回读校验。时间线、试听、量化和送入 FORGE 读取同一份录音。恢复后的相对时刻与事件字段保持原值；暂停浏览的时间在首次投球续录时排除，实际新球飞行时间仍计入。非空录音恢复时暂停自动投球，用户可手动投球或开启连发继续。清空同步更新缓冲与持久录音，关闭自动投球的设置也随状态保存。

测试使用 Windows 桌面浏览器的无头模式、临时浏览器配置与一次性 SQLite。受测源码摘要和全部检查项见 [机器指标](pinball_recording_metrics.json)。运行时间以该文件的 UTC 时间为准，转换到北京时间为 UTC+8。

存储拒绝写入时，录音保留在当前页面内存，并通过现有提示明确告知刷新可能恢复旧内容。刷新恢复以回读确认保存成功为前提。连续失败只提示一次，写入恢复后再次失败可重新提示。

复跑录音专项时，在修复工作目录执行以下命令。

```powershell
Set-Location D:/HoloBeat/.worktrees/v21-redesign
D:/Python312/python.exe 05_web_app/scripts/pinball_recording_e2e.py
```

项目根目录的 `一键启动.md`、`Start-HoloBeat.cmd` 与 `scripts/start-local.ps1` 同时安装到 `D:/HoloBeat`。主目录副本定位修复分支的工作树后执行该处最新脚本，前端使用 Vite 开发源码，后端使用当前 TypeScript 服务。每次启动都更新该入口管理的前后端进程。

Windows PowerShell 5.1 通过真实 `.cmd` 入口连续启动两次，后端 PID 从 38280 变为 45392，前端从 28044 变为 42800，第二次显示 `3039d16`。服务顺序为 /health 200、/generate 404、Vite 首页和 React 源码入口 200。此项使用隔离测试 SQLite；默认的用户数据库路径未用于测试。

Chrome 实际打开该入口提供的服务，29 张 WebP 均在浏览器解码，其 SHA‑256 逐个匹配修复分支中的 16 张角色图、12 张贴纸和 1 张舞台图，页面错误为 0。


启动回归另核对了 Vite 实际返回的弹珠页面包含当前录音恢复和同步保存逻辑。两次停止都正常释放所管理的进程。用测试监听器占用 5173 时，入口返回退出码 1，准确显示占用者 PID，测试监听器继续运行。在独立临时 Git 仓库模拟新增 UI 提交尚未合入的状态，入口在启动服务前返回退出码 1。四份启动日志的已知敏感值模式命中数为 0。主目录安装的三份入口文件与修复工作树逐文件 SHA‑256 相同。
